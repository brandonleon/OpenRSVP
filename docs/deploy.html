Deployment

Development and production setup

Run locally with uv or Docker, then deploy to a server with Nginx + Let's Encrypt HTTPS.

Stack FastAPI + SQLite

Local development (uv)

Best for code changes, quick debugging, and running tests.

uv venv
source .venv/bin/activate
uv pip install -e .

# run the app
uv run python main.py

# hot reload
openrsvp runserver --dev

# checks
uv run pytest
uv run ruff check
uv run ruff format
uv run pyright

Use openrsvp admin-token to fetch the root admin token and openrsvp seed-data for demo content.

Docker dev compose

Runs the container build with live reload enabled.

OPENRSVP_DATA_DIR=./data \
OPENRSVP_HOST_PORT=8000 \
docker compose -f docker-compose.dev.yml up --build

Browse http://localhost:8000. Override OPENRSVP_HOST_PORT to change the exposed port.

Production

Fresh server setup

Complete walkthrough from a bare server to a live HTTPS deployment.

Step 1

Prerequisites

  • Server running Amazon Linux 2023, Ubuntu 22.04+, or similar
  • Docker and Docker Compose v2 installed
  • Ports 80 and 443 open in your firewall / security group
  • A domain with its A record pointing at the server's public IP and DNS propagated

DNS must resolve before Let's Encrypt can issue a certificate. Verify with dig your-domain.com or nslookup your-domain.com.

Step 2

Clone the repo

git clone https://github.com/brandonleon/OpenRSVP.git
cd OpenRSVP

Clone to any directory — ~/OpenRSVP is a reasonable default. The SQLite database is stored in ./data/ by default, separate from the source tree.

Step 3

Configure your domain

Copy the example env file and fill in your values — this is the only configuration step required for a standard deployment.

cp .env.example .env
# Edit .env and set:
#   DOMAIN=your-domain.com
#   EMAIL=you@example.com

DOMAIN is injected into the nginx config via the official nginx image's built-in envsubst template support. No manual file editing needed.

Step 4

Issue the TLS certificate

Run the bootstrap script. It handles the chicken-and-egg problem between nginx and certbot automatically.

./scripts/init-certs.sh

The script reads DOMAIN and EMAIL from .env, temporarily loads an HTTP-only nginx config for the ACME challenge, obtains the certificate, then restarts nginx with the full SSL config.

You can also pass values as arguments: ./scripts/init-certs.sh your-domain.com you@example.com

Step 5

Start the full stack

docker compose up -d

This starts three containers: app (FastAPI on port 8000 internally), nginx (ports 80 and 443), and certbot (automatic renewal via crond).

The SQLite database persists in ./data/ across rebuilds. To use a different path, set OPENRSVP_DATA_DIR in .env.

Step 6

Verify and get the admin token

# Confirm HTTPS is working
curl -I https://your-domain.com

# Fetch the root admin token
docker compose exec app openrsvp admin-token

The root admin token grants full visibility across all events. Store it securely — it is not recoverable from the UI.

Operations

Ongoing maintenance

TLS Renewal

Automatic via crond

The certbot container runs crond internally and checks for renewal every 12 hours. On renewal, it signals nginx to reload without a restart.

To trigger a manual check:

docker compose exec certbot /renew.sh

The certbot container mounts /var/run/docker.sock to exec into the nginx container on renewal — a standard trade-off for single-server deployments.

Updates

Rebuild and restart

Pull new code and rebuild the image.

git pull --ff-only
docker compose up -d --build

The data directory stays on the host, so restarts do not wipe events or RSVPs.

Logs

Health and logs

docker compose logs --tail=200 app
docker compose logs --tail=50 nginx

# certbot renewal log
docker compose exec certbot \
  cat /var/log/certbot-cron.log

Use docker compose logs -f during deploys to watch for errors in real time.
